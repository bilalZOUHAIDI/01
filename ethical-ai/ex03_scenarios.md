# Exercise 3: Where Over-Reliance Breaks You

## Scenario 1: Technical Interview (Whiteboard System Design)

If I always use AI to create system designs for me, I can have a problem during a technical interview. Without AI or a compiler, I need to explain why I choose a certain architecture and why one solution is better than another.

For example, I should be able to explain things like latency vs throughput, consistency vs availability, and which data structure is better for a specific problem.

If I always let AI make these choices, I can get stuck when the interviewer asks me "why did you choose this?". I might know the final answer but not really understand the reason behind it.

---

## Scenario 2: Production Incident (AI Tools Unavailable)

If a production service suddenly crashes and AI is not available, I still need to be able to find the problem myself.

I need to understand things like memory, concurrency, locks, OS signals and network problems. I should be able to look at logs, stack traces or memory graphs and make a hypothesis about what is wrong.

If I depend too much on AI, I could just try random fixes without really knowing what is happening. This can waste a lot of time when the problem is urgent.

---

## Scenario 3: Learning a New Technology

If I want to learn a new library or framework that was released recently and ai doesnt know much about it yet, I cant just ask ai for the answer.

First, I would look at the official documentation and the source code. I would also check the tests to understand how the library is supposed to work.

Then I would make a small project and test different things myself. If something doesnt work, I would try to understand why by looking at the code and the error.

After that, I can do some tests or benchmarks to see how it performs.

---

## The Habit That Prepares Me

The main habit i learned from this quest is "Hypothesis Before Query".

Basically, before asking ai, i should first try to understand the problem and make my own hypothesis about what is happening.

This helps me build my own way of thinking instead of depending on ai for every problem. I can try things on paper, test my code and explain why i made a certain choice before asking for help.

This is useful for interviews, production problems and also when learning new technologies.

If ai is not available, i should still be able to continue working and find the problem myself. Thats why i think using ai as a tool for checking and learning is better than using it to do everything for me.
