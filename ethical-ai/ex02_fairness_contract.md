# Exercise 2: The Fairness Contract

This contract explains how I will use AI during my programming studies and projects. The goal is to use AI as a help, but not to let it do the work for me.

---

## 1. I will use AI when:

1. **After I tried to find the problem myself:**
   I will only show my code or bug to AI after I tested it myself and have an idea about what is causing the problem.

2. **For checking my code after finishing:**
   When my solution is already working, I can ask AI to check it and find possible edge cases, memory problems or other things I didn't think about.

3. **For understanding concepts:**
   If I don't understand something like tree rotations, graphs, cycles or bit manipulation, I can ask AI to explain the concept or give me an analogy. But I won't ask it to write the code for me.

4. **To test my understanding:**
   I can ask AI to give me questions or small test cases about my own code. This helps me see if I actually understand what I did.

---

## 2. I will NOT use AI when:

1. **Before trying the exercise myself:**
   I won't ask AI to give me a first solution, skeleton or boilerplate before I try to solve the problem myself. I should spend some time thinking about it first.

2. **During exams or graded tests:**
   I won't use AI during exams, piscine checkpoints or live audits where using it is not allowed.

3. **Just copying AI code:**
   I won't copy and paste code from AI directly into my project. If AI gives me an idea, I need to understand what it does and write the solution myself.

4. **To solve the whole exercise:**
   If an exercise is difficult, I won't just send the full subject to AI and ask something like "solve this in Go". I need to break the problem down myself first.

---

## 3. I know I am using AI fairly when:

1. **I can explain my code without AI:**
   If I close the AI chat and open an empty file, I should be able to explain and reproduce the main logic myself.

2. **I can modify my code myself:**
   If someone asks me to change something during an audit, like adding another delimiter or handling negative numbers, I should be able to do it without asking AI.

3. **I don't trust everything AI says:**
   I check the AI answer before using it. For example, if AI suggests a library that isn't allowed in the Piscine, I should notice it and not use it.

4. **I keep track of AI help:**
   When AI gives me useful feedback or points out edge cases, I can mention it in my notes or documentation so it's clear what kind of help I used.

---

## Evidence of Adherence on this Quest

For this quest, I followed these rules by:

1. Finding and fixing the whitespace bug in `SplitWhiteSpaces` by myself first, before using AI (`ex01_buggy.go` → `ex01_fixed.go`).

2. Using AI only after my solution was working, mainly to find edge cases and see if there was a cleaner way to do it.

3. Checking the AI answer myself and not using `strings.Fields(s)` because the Piscine rules don't allow the `strings` package for this exercise.

So AI was mainly used for checking and improving my understanding, not for doing the exercise for me.
